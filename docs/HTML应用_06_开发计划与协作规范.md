## 一、计划总览

- **交付目标**：一个纯静态只读的"家庭情景演练速查"HTML 应用，GitHub Pages 上线，手机可开、可离线。
- **关键约束**：**家庭正处第0周（9.3-9.6），9.21 进入"在家模拟园所周"每日执行高峰**——核心页须在 **9.18 前可用**，赶在在家周之前。
- **开发规模**：小（18 页 + 7 JSON + 轻量 SPA），无后端。数据抽取（52 剧本）是最大工作量。
- **建议节奏**：5 个 Sprint，AI 辅助开发约 **8-12 个工作日**完成 MVP。

## 四、GitHub 协作规范

### 4.1 仓库与分支
- 仓库：`family-scenario-training-app`（Public，Pages 免费版要求；无隐私数据）。
- 分支：`main`（可部署，保护）+ `feature/T0x-简短描述`；PR 合并用 Squash。
- 提交信息：`[T0x] 动词 + 对象`，如 `[T02] 抽取近期20剧本全字段`。

### 4.2 Issues / Labels / Projects
- **每个 WBS 任务 = 1 个 Issue**，正文含：输入文档、产出物、验收点、所属 Sprint。
- **Labels**：`sprint0`~`sprint4` · 角色 `data`/`ux`/`ui`/`content`/`arch`/`pm` · `红线`/`bug`/`enhancement`。
- **Projects 看板**：列 = Backlog / In Progress / Review / Done；按 Sprint 分组。
- **Milestones**：M1/M2/M3/M4 关联对应 Issue。

### 4.3 PR 与评审
- PR 模板：变更说明 + 关联 Issue + 自测结果 + 截图（页面类）。
- **内容红线 PR**（改 `scripts.json`/`safety.json`/话术/收益/激励）→ **必须内容专家 approve**。
- **CI**：`.github/workflows/validate.yml` 在 PR 触发 `node tools/validate-data.mjs`，失败阻断合并（禁语/计数/引用完整性自动化）。

### 4.4 环境与预览
- 本地：`npx http-server -p 8080`（勿用 `file://`，fetch 需 http）。
- 真机：手机同 Wi-Fi 访问 `http://<电脑IP>:8080`。
- 线上：合并 `main` 后经 Pages 自动发布，手机访问线上 URL 验收。

## 五、验收标准（Definition of Done）

### 5.1 数据验收
- [ ] `scripts.json` 计 52 条（近期20+中期19+长期13），`validate-data.mjs` 全绿；
- [ ] 每个 module/script/priority 的 `benefit` 非空、正向、≤60 字；
- [ ] 全站文案 0 命中禁语黑名单（`safety.forbidden`）；
- [ ] 里程碑 16 条与 §12.2 双标尺一致；编号/优先级/阶段与 §6.2 一致。

### 5.2 功能验收
- [ ] 5 个底部 Tab 全部可达、切换正常、当前态高亮；
- [ ] 首页"今天"按当前日期正确定位（今天 9.4 → 第0周·安全底座）；空档/超范围有回落不报错；
- [ ] 剧本库四维筛选可用；剧本详情含台词/角色/流程/原则/红线/收益/里程碑七要素；
- [ ] 大字卡模式可切换、可打印（只印台词+动作+编号）；
- [ ] 今日推荐遵守红线：防御类(B/C/A)当日≤1、以发展类收尾。

### 5.3 体验与无障碍验收
- [ ] 正文默认 ≥17px，大字模式 ≥22px；对比度 ≥4.5:1；点击区 ≥44×44px；
- [ ] 页面层级 ≤3；老人路径（角色 Tab→头像→大字卡）≤3 步；
- [ ] 优先级除颜色外均有文字标签（色盲友好）。

### 5.4 技术与红线验收
- [ ] GitHub Pages 上线，手机浏览器可开，相对路径无 404；
- [ ] PWA 可"添加到主屏"、离线可用（SW 生效）；
- [ ] **零后端、零数据库、零 localStorage 写入、零用户信息采集**（架构审查确认）；
- [ ] 无登录/注册/打卡/记录/排名/PK/惩罚机制。

### 5.5 交接验收
- [ ] README 含：项目简介、本地运行、部署步骤、内容更新指引（改 JSON→跑校验）；
- [ ] 8 份设计文档随仓库 `/docs` 归档；
- [ ] 内容更新 SOP 明确：只改 `data/*.json`，代码零改动。

# 家庭情景演练 HTML 应用 · 项目章程

> **文档定位**：本文件是"家庭情景演练 HTML 应用"项目的**总章程（入口文档）**，整合《专家团组建方案》与《功能设计 MVP》，并给出全套设计文档索引。
> **内容数据源**：`情景演练训练方案_v3.2修订版.md`（唯一权威内容源，附录三已确保数据干净）。
> **版本**：v1.0 · 2026-09-04 · 由产品席（PO + 内容守门人）牵头产出。

## 〇、一句话定位（不可动摇）

> **本应用 = "V3.2 家庭速查手册"——纯静态 · 只读 · 零后端 · 零维护 · 不采集任何数据。**
> 只帮家人用手机**看懂**：今天/本周演什么、剧本和角色是什么、整体计划是什么、对孩子有什么好处。

### 范围红线（用户明确排除，任何角色不得引入）

| 明确不做 | 说明 |
|---------|------|
| ❌ 用户信息 | 无登录、无注册、无个人档案、无账号体系 |
| ❌ 后端 / 数据库 | 无服务器、无 API、无云端存储 |
| ❌ 系统维护 / 状态持久化 | 无打卡、无贴纸集章、无观察卡记录、无 localStorage 写入 |
| ❌ 多孩子 / 多家庭配置 | 本家庭专用（单孩子），内容硬编码当前情境 |
| ❌ 增长黑客机制 | 无排名、无对比、无 PK、无断签惩罚（违反孩子主权红线） |

> **"今天/本周"如何实现（无后端）**：前端用 `new Date()` 对**静态日历数据**做只读匹配，纯客户端计算，不存储任何用户状态。

## 第一部分 · 专家团组建方案

### 1.1 团队组织（4 席 · 7 核心角色 + 1 评审席）

本项目区别于普通 App 团队的关键：**产品席内设"内容守门人"**，继承 V3.2 五方专家团，对儿童安全红线持一票否决权。

| 席位 | 角色 | 一句话定位 | 现阶段主责交付物 |
|------|------|-----------|-----------------|
| **产品席** | ① 产品负责人（PO） | 定义"做什么、为谁做、先做什么" | 功能设计 + 产品设计（本章程第三部分） |
| **产品席** | ② 儿童发展内容专家（**内容守门人**） | 守护 V3.2 方法论与儿童安全红线 | 内容规格 + 全程红线 gate |
| **设计席** | ③ 体验设计师（UX/交互） | 定义"怎么用"，含老人可用性 | 信息架构 + 导航模型 + 核心流程 |
| **设计席** | ④ 视觉设计师（UI） | 定义"长什么样"，儿童友好+移动端 | 设计系统 + 高保真原型规格 |
| **技术席** | ⑤ 前端架构师（技术负责人） | 定义"怎么搭、怎么上线" | 技术选型 + 架构 + 目录 + 部署 |
| **技术席** | ⑥ 数据内容工程师 | 把 V3.2 变成干净的结构化数据 | 数据模型 + JSON Schema + 样例 |
| **交付席** | ⑦ 交付项目经理（PM） | 定义"何时做完、怎么协作" | 开发计划 + GitHub 工作流 + 验收 |
| **评审席** | ⑧ 家庭用户代表（体验官） | 代表妈妈/老人/爸爸真实使用 | 可用性走查（评审参与） |

### 1.2 分角色职责与 V3.2 锚点

- **① 产品负责人（PO）**：功能清单、MVP 边界、信息组织、需求取舍。锚点：把"每日 10-15 分钟、防御类剧本≤1/天、以发展类收尾"（§11.1、§15）落进内容逻辑。
- **② 内容守门人**：把 V3.2 方法论/话术/红线转译为内容规格；审查一切面向孩子与家长的文案，防止"创伤预演"或"打卡逼迫"。锚点：孩子主权（§5.1）、禁语清单（§5.4）、心理安全监测与降级（§14）、"严禁扣贴纸惩罚失败"（§11.1）。**凡涉及剧本/话术/收益/激励的产出须过此角色审查。**
- **③ 体验设计师（UX）**：信息架构、导航、查阅体验、老人极简模式。锚点：§8.3 老人执行支持（大字、台词锁死、示范视频）转化为可交互设计。
- **④ 视觉设计师（UI）**：视觉语言、设计系统、高保真原型、可打印大字卡。锚点：视觉服务"去舞台化、儿童友好"，不渲染"幼儿园很危险"（§3.1）。
- **⑤ 前端架构师**：静态站/PWA 技术选型、架构、目录、GitHub Pages 部署。因只读定位，**无隐私/状态/后端架构负担**，聚焦静态站与日期视图。
- **⑥ 数据内容工程师**：把 12 模块/52 剧本/双标尺里程碑/日历/话术/收益抽成干净 JSON；校验对齐附录三。锚点：里程碑以 §12.2 为唯一权威；剧本数以 §6.3（52=20+19+13）为准。
- **⑦ 交付 PM**：WBS、排期、GitHub 协作流、验收标准（DoD）、风险登记。
- **⑧ 家庭用户代表**：在功能评审、原型走查两节点，用"真实家庭晚间 10 分钟"视角挑刺，确保"老人能看懂能照做"（§2.3、§8.3）。

### 1.3 角色 × 交付物 责任矩阵（RACI）

> R=负责执行 · A=最终批准 · C=需咨询 · I=需知会 · 🔒=红线 gate

| 交付物 | PO | 内容专家 | UX | UI | 架构师 | 数据工程师 | PM | 用户代表 |
|--------|:--:|:-------:|:--:|:--:|:-----:|:---------:|:--:|:-------:|
| 功能设计 | A/R | C🔒 | C | I | C | C | I | C |
| 产品设计（IA/导航/流程） | A | C🔒 | R | C | I | C | I | C |
| 原型设计（视觉/设计系统） | C | C🔒 | C | A/R | I | I | I | C |
| 内容规格（收益/禁语/红线） | C | A/R🔒 | I | I | I | C | I | C |
| 数据模型与 Schema | C | C🔒 | I | I | C | A/R | I | I |
| 开发框架设计 | I | C🔒 | I | I | A/R | C | C | I |
| 开发计划制定 | C | I | I | I | C | C | A/R | I |

### 1.4 协作流程（5 + 1 阶段序列）

```
阶段0 共识基线 → 阶段1 功能设计 → 阶段2 产品设计 → 阶段3 原型设计 → 阶段4 开发框架 → 阶段5 开发计划 → 汇总
（全员）        （PO+内容）      （UX）          （UI）         （架构师+数据）  （PM）        （PO+PM）
                                     └────── 内容专家 🔒 红线 gate 贯穿全程 ──────┘
```

- **评审席介入点**：阶段1（功能评审）、阶段3（原型走查）。
- **可并行**：阶段3（原型）与阶段4（框架）可部分并行。

### 1.5 GitHub 协作基线

| 项 | 基线 |
|----|------|
| 托管 | GitHub Pages（静态站，手机浏览器直开，可"添加到主屏"） |
| 仓库结构 | `/docs`（设计文档）· `/data`（V3.2→JSON）· `/src` 或根目录（HTML/CSS/JS）· `/assets`（图标/大字卡/绘本单） |
| 协作流 | Issues=需求/任务卡（标签：功能/设计/技术/内容/红线）· Projects 看板=交付物 · Milestones=设计期/开发期/上线 |
| 分支 | `main`（自动部署 Pages）+ `feature/*`；涉及剧本/话术/收益的 PR 需内容专家 approve |

### 1.6 从 V3.2 继承的 7 条设计红线（不可谈判）

1. **孩子主权优先于任何进度**：不得用惩罚/扣分/断签施压；"严禁扣贴纸惩罚失败"（§11.1、§5.1）。
2. **心理安全监测内置**：预警信号 + 降级流程须可被家长快速触达（§14）。
3. **禁语过滤**：所有文案/话术卡严格避开诱导性负面提问与禁语（§5.4）。
4. **防御不越界**：防御类剧本≤1/天，以发展类收尾，不渲染"幼儿园很危险"（§11.1、§3.1）。
5. **老人可照做**：大字卡、示范视频、台词锁死≤2 句、极简层级（§8.3）。
6. **数据单一权威**：以 V3.2 为唯一内容源，里程碑以 §12.2 双标尺为准，剧本数以 §6.3（52）为准。
7. **只读无采集**：不采集、不存储任何用户/孩子数据（用户明确要求）。

## 第二部分 · 功能设计 MVP（只读版）

### 2.1 MVP 定位

> **MVP = "近期地基期（9-10 月）只读执行速查"**——让妈妈今晚就能打开手机，看懂"今天/本周演什么、怎么演、谁配合、为什么练"，一直用到 10.16 返园重启周。

- **数据模型硬编码**（单孩子/单家庭）：女宝（入园时3岁9个月）、7 名成员、小班（园所信息已脱敏）、§1.1 关键日历直接内置。
- **时间基准**：今天是 2026-09-04（周五），家庭正处 V3.2 "第0周安全底座（9.3-9.6）"。首页须自动定位到当前节段。

### 2.4 "对孩子的收益"取数专项（用户新增强调，一等公民）

散落在 V3.2 各处的"为什么"归集为可展示维度：

- **总纲**：§2.2 建立"被伤害→喊停→表达→求助→走开"新神经通路；§4.3 核心公式（演练+成功体验+庆祝=新条件反射）；§4.2 治本结论（情绪稳+能自理+守规则+会表达+有朋友→几乎不会被欺负）。
- **分层收益**：§3.3 每层"为什么排 PX"。
- **分剧本收益**：§6.2 各剧本"核心训练点"→ 由内容专家改写为"练这个，孩子能获得什么"。
- **达成收益**：§12.2 里程碑"孩子最终能做到什么"。
- 👉 **数据工程师 + 内容专家**为每个模块/剧本补一个 `benefit`（收益）字段。

### 2.5 MVP 范围三栏

**✅ MVP（纯只读速查手册，一次成型）**：5 大板块骨架 + **近期 9-10 月内容完整填充** + 全部安全/话术/收益参考页。中长期剧本数据可一次性导入（成本低），首页"今天/本周"按当前日历只推近期。

**🔜 后续可选增强（非必须）**：示范短视频外链聚合、绘本书单页、可打印大字卡模板美化。

**⛔ 明确不做**：见"范围红线"表（用户信息/后端/系统维护/打卡记录/多家庭/增长机制）。
